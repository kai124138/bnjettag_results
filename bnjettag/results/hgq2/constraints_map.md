# Constraints map — what each layer type can/can't do through HGQ2 (0.1.9) + hls4ml (1.3.0)

Written 2026-07-04 during the HGQ2 rebuild of the era-2 BitNet transformer. Every row was
**established by execution** (local C-sim = compile()+predict on the Vitis backend, or a
failed conversion with the exact error), not by reading docs. Purpose: future model designs
start from this table instead of trial-and-error. Source of each finding: `code/hgq2/LEDGER.md`.

## Verdict legend
✅ converts + bit-exact · 🟡 converts with caveats · 🛠 needs the custom-layer recipe · ❌ blocked

| Construct | Verdict | Detail |
|---|---|---|
| **Binary {−1,+1} weights** | ✅ | `KBI(k0=1, b0=1, i0=1, RND, SAT_SYM, trainable=False)` passes ±1 kernels through bit-identically and reports **1 bit** to EBOPs. Representable set is {−1,0,1}; 0 is unreachable for pinned ±1 kernels (values outside ±0.5 would be needed). `b0=0` is a trap: representable set collapses to {0}. |
| **BitNet per-tensor β scale** | 🟡 | Arbitrary float β as `QuantizerConfig(scaler=β)` breaks bit-exactness (weight_t inflates to fixed<24,0>). **Power-of-2 β is too lossy end-to-end** (−6.3 AUC pts at A8 across 51 layers, measured). The working recipe is **fold-aware**: Q/K β exact via the softmax `input_scaler` (exp-LUT fold, free); V β dropped exactly (next LN is scale-invariant); fc1/head_fc1 β exact via bias→b/β (next LN kills the scale); only residual contributors (input_proj, Wo, fc2, head_fc2 = 2L+2 sites) carry a CSD-2 β̃ (2-signed-digit, ≤4.5% err). Measured cost at A8: −0.003 AUC vs exact β. **CRITICAL placement rule (measured the hard way): β̃ must live in a separate affine layer (frozen QBatchNormalization, ε=0), NOT in the weight values** — see the Resource-mode row below. |
| **Resource-strategy ROM weights vs the ≤2-digit rule** | ❌→🛠 | **The Vitis ≤2-signed-digit DSP-free rule applies ONLY to compile-time constants.** With `Strategy: Resource` (the RF-folded deployable point), hls4ml stores weights in BRAM/ROM — runtime operands — and Vitis infers REAL multipliers: in-weight ±β̃ (an ~8-bit fixed value) synthesized to **256 DSPs** on a 256×256 "binary" dense at RF=256 (measured; the QKeras frontend avoids this only because it emits literal 1-bit `ap_uint<1>` weights with a dedicated `weight_binary` product class — the HGQ2/keras-v3 frontend has no such special-case). Fixes, in order of preference: (1) keep datapath weights **pure ±1** (2-bit operands) and carry β̃ in a downstream affine; (2) `Strategy: Latency` (weights inlined as constants) — **csynth-verified DSP-0** for dense AND affine at small shape (head_fc2, RF=32). |
| **Latency strategy at big shapes** | ❌ | A 256×256 (65k-MAC) Latency dense at RF=256 **crashed Vitis 2023.2 after 4 h of elaboration** (`HLS 200-1715 problem during source synthesis`, following hours in Compile/Link) — the fully-unrolled code explosion prior art documented as intractable. So: **small shapes (deployable-scale models) → Latency, DSP-0 verified; big shapes → Resource is the only tractable folded point**, where DSP-0 on the HGQ2 path still needs the frontend to emit true 1-bit weight types + the `weight_binary` product class (the identified, bounded next engineering item — or quote the QKeras-path per-shape numbers, which already prove DSP-0 at Resource/RF=256 for those shapes). |
| **Static activation quantizers** | ✅ | `KIF(k0=1, i0, f0, RND_CONV, SAT, trainable=False)`. RND_CONV = ties-to-even matches TF/numpy. Per-element heterogeneous i/f is native (io_parallel wires). **Per-channel MSE-optimal calibration beats max-calibration** decisively at low bits (A4: ΔAUC −0.078 → −0.017, measured). |
| **Dynamic per-token activation scaling (BitNet training-time quant)** | ❌ | Unimplementable in static fixed-point — no hls4ml/HGQ2 equivalent exists. Any rebuild substitutes static grids; measure the substitution, don't pretend it's free (A8 −0.005, A6 −0.017, A4 −0.017 AUC at per-channel-MSE calibration). |
| **Datalane defaults (the WRAP trap)** | 🟡 | Every unconfigured HGQ2 datalane quantizer defaults to **WRAP + trainable, uncalibrated**. At inference this silently wraps out-of-range values → garbage outputs with no error (cost one full debug round: AUC 0.50). Rule: **every quantizer in the graph gets an explicit frozen config**, or run `trace_minmax` calibration for WRAP ones. |
| **LayerNormalization (keras)** | ❌→🛠 | Blocked three verified ways in keras-v3/hls4ml-1.3.0 (no v3 handler; v2 fallback needs axis=(2,) and learnable γ/β; BitExact has no `produce_kif`). Also the stock `nnet_layernorm.h` inv-sqrt table only covers var ∈ (eps,1]. **Fixed via the custom-layer recipe**: `PSubLN` keras layer + keras-v3 handler + new `SubLN` IR + `_produce_kif`/`_request_kif` + Vitis templates + `nnet_subln.h` with range-reduced 1/√ (even-power-of-two shift onto [1/4,1), 4096-entry table, half-shift back). C-sim corr ≥ 0.9999999 for dims 16/256/1024, input var 0→1e6. Table-based ⇒ near-exact, not bit-exact. |
| **QMultiHeadAttention (native)** | 🟡 | Works and is bit-exact through hls4ml, BUT two 0.1.9/1.3.0 compat bugs need shims (registry key module path; keras-3.15 removed `EinsumDense.full_output_shape`) — `bnhgq2/compat.py`. Its internal structure is fixed: no hook to insert a norm before the output projection (SubLN-inside-Wo cannot be expressed) → for this model, compose from the same primitives instead. Key projection never gets a bias (hardwired). |
| **QEinsum (act×act contractions)** | 🟡 | The attention-core enabler (scores=QKᵀ, ctx=attn·V) — converts to the Einsum IR, **io_parallel + Latency strategy only** (RF acts via `multiplier_limit`). Upstream bug: `enable_iq=False` crashes `build()` on multi-input layers (`_iqs_confs` typo) — use explicit exact-passthrough frozen SAT grids instead (identity on the integer streams, keeps EBOPs live). |
| **QSoftmax** | 🟡 | Table-based stable softmax (exp LUT + inv LUT), bit-exact through hls4ml. `input_scaler` folds an arbitrary constant into the exp table for FREE — the sanctioned place for score scales (β_qβ_k/√d). Its exp/inv INPUT quantizers are WRAP datalane defaults (same trap) — set frozen SAT grids sized from calibrated score ranges; negative `f0` is legal and right for coarse-but-covering grids (score gaps ≫ step). Table sizes = 2^bits of the input grids — keep ≤ 12 bits. |
| **QEinsumDense** | ✅ | The workhorse. Head split/merge lives in the equation (`btd,dhe->bthe`, `bthe,hed->btd`) — no Reshape needed. `bias_axes` spanning non-channel axes gives quantized additive constant TABLES. |
| **Positional encoding (additive constant)** | ✅ | keras `Embedding` is blocked under BitExact (no produce_kif). Fold the PE table into the input projection's `bias_axes='td'` bias: exact, quantized, zero extra ops. (This model's PE is an untrained folded constant — extracted from the checkpoint's `model_config` JSON, not from weights.) |
| **Residual Add (float)** | ✅ | keras `Add` via the merge handler; BitExact carries exact growing widths. No broadcasting in `nnet_merge.h` — shapes must match exactly. |
| **GlobalAveragePooling1D** | 🟡 | `QGlobalAveragePooling1D` converts + bit-exact; non-power-of-2 sequence length (T=10) makes 1/T binary-infinite → very wide accumulator fraction. Acceptable at the head; avoid in hot paths. `QSum`/`QMeanPow2` have no keras-v3 handler. |
| **ReLU** | ✅ | plain keras layer, standard support. |
| **Rescaling / constant Multiply** | ❌ | no keras-v3 handler, no v2 fallback (without da4ml installed). Use `QBatchNormalization` (frozen per-channel affine, bit-exact) or fold into quantizer scalers / softmax input_scaler / bias tables. |
| **3-D QDense** | 🟡 | silently re-parsed as PointwiseConv1D — use QEinsumDense for 3-D instead (explicit, predictable). 2-D QDense is fine. |
| **hls4ml `bit_exact` kwarg** | 🟡 | `convert_from_keras_model(..., bit_exact=None)` silently OVERWRITES `hls_config['Model']['BitExact']` — always pass `bit_exact=True` explicitly. |
| **macOS local C-sim** | 🟡 | patch `ap_{int,fixed}_special.h` (std::complex fwd-decl → `#include <complex>`) AFTER `write()`, then `_compile()` (plain `compile()` re-writes and undoes it). Linux/mulder unaffected. |

## Where DSPs can hide (for the DSP-savings claim)
1. **SubLN**: variance + inverse-sqrt path — the model's known DSP consumer (old
   fixed<32,16> LayerNorm census: 1,049 DSP = 100% of model DSPs). The new range-reduced
   `nnet_subln.h` has 42×42-bit squares → measure, don't assume (csynth pending).
2. **Arbitrary-constant multiplies**: any const with >2 signed CSD digits may infer a DSP
   (Vitis rule, verified in literature). Keep every hardware constant ≤2 signed digits
   (power-of-2 or CSD-2) — β̃ snapping exists exactly for this.
3. **Wide accumulators** (GAP's 1/10, exact einsum streams) — adders, not multipliers:
   LUT cost, not DSP. But watch synthesis.
4. The binary matmul cores themselves: DSP=0 **structurally** (1-bit weights are
   wire/negation) — confirmed in prior csynth at A8/A6/A4 and re-checked per new probe.

## Addendum 2026-07-07 — full-monolith conversion of the FINAL QAT model (convert_final.py)

New rows established by executing the whole-model convert + local C-sim (not probes) on the
real `final-smoke` w1a8 checkpoint. Same legend.

| Construct | Verdict | Detail |
|---|---|---|
| **ReLU output width vs wide binary contractions** | 🛠 | `keras.layers.ReLU` is parsed by hls4ml 1.3.0 as `ParametrizedActivation('thresholdedrelu')` whose BitExact-assigned output precision is **UNSIGNED + WRAP**. A negative input then **wraps to ~2^i** instead of clamping to 0. On the binary FFN, fc1 = a 256-wide ±1 contraction of a ±4-clipped SubLN input spans ±O(2^10), so ~half the ReLU outputs (the negatives keras zeroes) explode to ~1024 → full-model C-sim corr **−0.06**, max|Δ| = **1023.999** = 2^10 exactly. **Fix (bit-exact):** set the relu-family output precision `saturation_mode = SAT` post-parse (`convert_final.fix_relu_saturation` via the new `convert(post_parse=…)` hook) — negatives saturate to 0. Full-model C-sim −0.06 → **≥0.997**. General rule: **any relu whose input is a wide binary/int accumulator needs SAT (not WRAP) on its output**, else negatives wrap by 2^i. |
| **EinsumDense strategy** | ❌(Resource) | hls4ml 1.3.0 EinsumDense codegen asserts `EinsumDense layer only supports Latency strategy for now`. The FINAL model is EinsumDense-dominated (input_proj + all Q/K/V/O + fc1/fc2), so the **full model cannot use Resource** folding — it MUST be Latency (RF → einsum `multiplier_limit`). Consequence for mulder: the big-shape Latency wall (see the row above) applies to the monolith; the per-block/per-shape probe path stays the deployable route. |
| **ValidateResourceStrategy vs EinsumDense** | 🛠 | The Vitis QoR-warning pass matches `EinsumDense` via the `'Dense'` substring but `get_layer_mult_size` returns `n_in=None` for einsum → `rf > n_in` raises `TypeError`, killing conversion. Guard: `convert_final.patch_resource_einsum_check()` (skip when n_in is None; the pass only prints a urem note). |
| **Datalane quantizer `scaler` through hls4ml** | ❌ | HGQ2 `Quantizer.scaler` (the exact non-power-of-2 per-tensor scale) is **dropped** by the hls4ml frontend: `keras_v3/hgq2/_base.py extract_fixed_quantizer_config` reads only `internal_q.kif` + SAT/RND. So reproducing the TRAINED attention grids under the β-fold via `scaler=1/β` (which lifts gate-1 to ~0.99 in keras) is **keras-only** — measured: a converted copy_qat project's gate-2 collapses. Exact hardware reproduction needs either non-power-of-2 scale support in that frontend, or ±β projection weights (which cost DSP on the Q/K/V projections). Default export keeps pure ±1 + power-of-2/CSD-2 folds (`attn_grids='build_default'`). |

## Addendum 2026-07-09 — MEASURED csynth outcome of the FINAL-flagship per-shape probes (mulder)

| Construct | Verdict | Detail |
|---|---|---|
| **Latency einsum-dense ≥~40k MACs → clang LTO non-convergent** | ❌ | csynth of the flagship per-shape probes on mulder (run8_parallel, 3 h timeout): the **binary EinsumDense probes at Latency/RF256 do NOT converge** — `clang -cc1` pinned at 100 % CPU for the FULL 3 h and never reaches a report (LTO non-convergence, NOT a wedge). Measured 3×: `attn_qkv` (256→256, 65k MACs), `attn_Wo` (65k), `ffn_fc1` (256→1024, 262k). **Root cause = EinsumDense being Latency-strategy-ONLY** (row above): at Latency the folded RF does **not** reduce the inlined-constant weight volume, so the fully-unrolled ±1 constant array explodes clang LTO for large shapes. **The small einsum/dense is fine:** `head_fc2` (256→5, 1.3k MACs, 2-D QDense) synthesized rc=0 in **6 min**. The attention core (RF=64) is a separate long-runner (3.5 h+ in "global binding", not a crash). **Fix = re-emit the big binary shapes as 2-D QDense at Resource strategy** (the §6′-proven route; `probes_final_v2.py`) — Resource folds the weights into ROM so LTO stays bounded. |
| **HGQ2-path binary Dense at Resource: DSP-0 vs the 1-bit-emission gap** | 🟡 | At Resource, the ≤2-CSD DSP-free rule does NOT apply (ROM operands, row above). DSP-0 for the binary dense therefore needs the frontend to emit **true 1-bit weight types** (the QKeras path had a dedicated `weight_binary` product class; the HGQ2/keras-v3 path does not — measured 2026-07-04: pure ±1 at RF=256 Resource inferred **256 DSP** in the dense, SubLN 14, affine 0 = 270). So the honest expectation for the v2 Resource probes is recorded **both ways**: DSP-0 IF the emission produces 1-bit weight types, else a ~256-DSP (270-with-SubLN) reading — the mulder number is the arbiter. Trap avoidance IS applied (pure ±1 datapath + β in a frozen CSD-2 affine — never in-weight ±β, which is a guaranteed 256-DSP ROM trap). **UPDATE (root-caused, see next row): the 256-DSP is NOT the 1-bit-emission gap — it is the accumulator precision.** |
| **Binary-dense DSP at Resource is set by the ACCUM precision, not the weights (root cause, 2026-07-09)** | ✅ | v2 csynth split (fc1/head_fc1/input_proj = 0 non-norm DSP; qkv/Wo = 256) root-caused from the emitted projects + csynth XMLs: **all** three ROMs are pure ±1 (`weight_t ap_fixed<2,2>`), same `ap_fixed<8,3>` input, same `nnet::dense_resource` kernel — the ONLY difference is the DENSE ACCUMULATOR. Wide-frac accum `ap_fixed<27,11>` (fc1: BitExact widened it to feed the downstream ReLU/LN) → Vitis maps the ±1 MAC to **LUT → 0 DSP** (111k LUT); narrow-frac accum `ap_fixed<16,11>` (Wq/Wk/Wv/Wo: BitExact minimized it to the exact-passthrough score-stream request) → Vitis maps it to a **DSP48 → 256 DSP** (15k LUT). Verified REAL (not a probe artifact): the full flagship's Wq/Wk/Wv/Wo all carry `ap_fixed<16,11>`. **Fix = widen the dense accum (frac ≥ 16, keep integer range) → 0 DSP, bit-exact** (the accum is only more precise; the downstream re-quantizes to its grid — C-sim 0.9999999, `probes_final_v3.py` `widen_dense_accum`). So it is a genuine **DSP↔LUT trade** controlled by the accumulator, NOT a frontend gap: **the ENTIRE final stack CAN synthesize DSP-free (all DSP in the norm) by widening the 4L attention-projection accumulators**; the default BitExact-minimal accum parks 256 DSP in each. (input_proj already wide `<24,8>`→~0; fc2 wide `<18,14>`.) |
